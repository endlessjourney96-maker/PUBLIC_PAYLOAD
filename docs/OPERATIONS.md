## 現在のクリティカルパス

**公開MVP → 実ユーザー流入 → 診断完了 → 推薦クリックの実測**。

公開物の追加より先に、実測可能な導線を成立させる。報酬額は推薦順位に混ぜず、課題適合・予算・無料代替の有無を優先する。

## 現在の永続成果物

- `index.html`: 3問診断、無料改善案、必要時のみAI/SaaS推薦、買わない判断、ブラウザ内イベント計測。
- `meeting-minutes-pm.html`: PM/管理職×議事録課題の検索流入用入口ページ。
- `docs/OPERATIONS.md`: 次回サイクル再開用の本ファイル。

## 現在の計測イベント

`index.html` はブラウザの `localStorage` (`mvp_events`) に以下を保存する。

- `page_view`
- `entry_attribution`
- `diagnosis_start`
- `diagnosis_complete`
- `recommendation_click`

現時点ではサーバー集計ではないため、**PV・クリック・CV・売上の全体実績値として扱わない**。実績値は取得できた場合のみ報告する。

## 推薦原則

1. まず0円改善を提示する。
2. 予算0円なら原則「買わない」を候補にする。
3. 有料候補は課題適合と予算適合で絞る。
4. アフィリエイト報酬額はランキングに使用しない。
5. 価格・機能・規約は変更され得るため、購入前に公式情報へ誘導する。
6. 将来の物理商品・楽天ラクヨコ・ふるさと納税等も同じ候補データモデルへ寄せる。

## 次の優先アクション

1. **最優先:** 実ユーザーが流入した際に、匿名かつ同意・規約面で安全に集計できる計測方式を設計する。追加固定費は売上前 月2,000円以下を目標とする。
2. `meeting-minutes-pm.html` に続く検索意図別入口ページを1本追加し、診断へ `source` / `campaign` / `pain` を引き継ぐ。
3. 推薦候補をHTML直書きから共通データへ分離し、AI/SaaS・物理商品を同一スキーマで扱えるようにする。

## QAスモークテスト

公開変更後は最低限以下を確認する。

- トップページがスマホ幅でも横スクロールしない。
- 3つのselectを変更して診断できる。
- 予算0円で「買わない」が表示される。
- 有料予算で候補カードが表示される。
- 推薦リンクは別タブで開き `noopener noreferrer` を維持する。
- `meeting-minutes-pm.html` のCTAから `role=manager&pain=meeting` が引き継がれる。
- 開発用KPIを実績値と誤認しない。
